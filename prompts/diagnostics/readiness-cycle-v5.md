## Порядок

1. Подготовить новый runtime/paths и CPU-preflight. Проверка H100 — максимум два вызова настоящего typed tool→receipt→proposal пути; это отдельная оплаченная стадия в ledger. Никаких незаявленных health-generations.
2. Выполнить уже выбранные nominal prefix4 / induced prefix5, по два traveler tasks, с прежними actor prompts/spec и конечными лимитами. На handoff обе private goals удаляются по origin, настоящие переговоры сохраняются. Диагностика фиксирует source-first references до просмотра памяти.
3. Проверить одну заранее объявленную версию memory builder на known1 regression и реальных A/B sources4/5. Новая C-схема maxItems24 и budget-aware prompt объединяют только связные сведения одного traveler/day/status; это одна генерация, не post-hoc merge. All material conjuncts проверяются V. Chronological whole-record prefix, общий content cap2048, прежний codec, CVP⊆CV⊆C и no backfill сохраняются. Balanced/round-robin selection в действующий метод не входит.
4. Интегрировать общий exact source descriptor request / explicit finality notice / supplied plan fields. Notice может подтверждать объявленный статус provided-final; оно не доказывает соблюдение запроса, выбранные объекты, booking или commit. Query-only не даёт plan status. Старые output/labels/primary failure не исправляются задним числом.
5. После DEV зафиксировать единые H100 code/prompts/schemas/task policy/rules до открытия новых6/7. Обе группы остаются final DEV validation, не main. Зафиксировать source-first references, затем выполнить их S/C/V/P, шесть изолированных memory arms × tasks3/4 и 16 заранее locked V/P fixtures. Каждый job имеет terminal status/not-run reason; все24 назначенных post-handoff opportunities сохраняются даже при fatal на первой группе.
6. Cache-only replay, фактический wire/visibility/origin audit, H/U/Q/initialQ, formation evidence, расходы и GPU release. Показать отдельные техническую готовность и научную информативность. Малое число групп не превращать в population precision через bootstrap полей.

Исполнитель владеет production/server, диагностика — `diagnostics-v5/`, дизайн координирует и проверяет. Разрешённые локальные engineering fixes выполняются без microquestions человеку; новые model calls требуют только конкретного phase review/dispatch внутри этого поручения. При смене метода после final freeze сохранить новый fingerprint и независимую проверку, не переписывать удобные results.

После реального A/B/E предъявить владельцу конкретный основной manifest: выборку/eligibility/stopping, N, ε, analysis, human audit status, стоимость и команду запуска. Основной сбор, включая test-prefixes, остаётся закрыт до его явного одобрения. AI reference/audit не называются человеческими.
